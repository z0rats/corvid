# Corvid — project context

Self-hostable, single-user OSINT/security-analyst web app. FastAPI backend + React frontend, runs via Docker Compose. Early prototype, not production-hardened.

**Maintenance:** this file loads in full on every message regardless of task, so its size is a standing tax on every conversation — treat growth as a cost, not a free action.

- Update it after any important project change (new feature, new external dependency, architectural shift) — but each edit is a *net* pass: prune or tighten something (merge, generalize, cut what's now covered elsewhere or obvious from the code) roughly as much as you add. Don't just append.
- Record big architectural decisions (new dependency choice, schema/storage tradeoffs, anything picking one approach over a real alternative) as a new `docs/adr/NNNN-*.md` in `docs/adr/TEMPLATE.md`'s format (from 0023 on, `test_adr_format.py` requires `## Decision` and `## Rejected`, each rejected alternative with its reason) — don't let the reasoning live only in chat/commit history. Keep entries in this file itself pointer-short; the ADR holds the "why".
- Never cite an uncommitted plan/spec/audit file: the lasting "why" goes in an ADR, the "how" in `docs/architecture/`. Drift gates: `scripts/check_doc_references.py` (dangling `docs/*.md` refs; pre-commit + CI), `.github/scripts/check-docs-coverage.mjs` (feature pages, scan `source` values, Settings tabs), `backend/tests/core/test_env_docs_sync.py` (env vars).
- For a feature/subsystem whose implementation detail (exact mechanisms, gotchas, edge cases) has grown past a couple of sentences, move that detail into `docs/architecture/<slug>.md` (not loaded every turn, so no size pressure there) and leave a 2-4 sentence summary + `Deep-dive: docs/architecture/<slug>.md` pointer here. This file should stay a map to where deeper info lives, not the deep info itself.
- Describe the **current state only**. No "was X, changed to Y because Z", no "see commit/PR #123", no incident narratives or migration history — that's git history, queryable on demand. If a past decision needs to stay discoverable, a short present-tense reason clause (e.g. "X, since Y" ) is fine; a paragraph of backstory is not.
- No speculative or redundant detail.
- If this file is pushing 35KB+, that's a signal to condense before adding more — collapse verbose bullets, drop detail that's redundant with the code itself, and prefer pointing at a file/symbol or a `docs/architecture/<slug>.md` deep-dive over re-explaining what it does.
- Also update `README.md` for user-facing changes, especially deployment ones (new setup step, changed env vars, `.env`/`docker-compose.yaml` behavior) — operators read it when installing/upgrading.

## Git

Run `git commit` / `git push` (or create tags or releases) ONLY when the user directly asks for that specific action in their message (e.g. "commit this"). Otherwise stage or leave changes uncommitted and let the user review. A broader instruction ("go ahead and update the repo", "ship this", "fix everything") does not count as a direct request, no matter how routine the change looks. A direct request covers only the action named, not later ones: approval to commit is not approval to push, or to commit again later.

## Stack

- **Backend**: Python 3.14, FastAPI, SQLAlchemy 2.0 (async, `aiosqlite`; SQLite only - a non-SQLite `DB_URL` fails at startup, `docs/adr/0004-sqlite-only-postgres-unsupported.md`), Alembic migrations, APScheduler for background jobs, `pydantic-ai-slim[anthropic,openai]` for LLM features (not the `pydantic-ai` metapackage, which hard-depends on every provider SDK; `app/utils/llm_service.py`'s model registry also auto-discovers models pulled into a local Ollama server via its OpenAI-compatible `/v1/models` endpoint - `LLM_OLLAMA_BASE_URL`, no API key needed, silently skipped if unreachable), `slowapi` for rate limiting, pytest for tests.
- **Frontend**: React 19, MUI 9, Jotai (state), react-router 8 (declarative mode only - `BrowserRouter`/`Route`/hooks imported from `react-router`, not the removed `react-router-dom` package), Vite (build/dev server) + Vitest (tests, jsdom), ESLint 10 flat config (`frontend/eslint.config.mjs`), Yarn 4 (berry, `packageManager: yarn@4.15.0`). TypeScript is being adopted incrementally (`allowJs`, convert-on-touch, no bulk rewrite); `typescript` is pinned below latest (`~6.0.3`) since `7.x`'s package-layout change breaks Yarn 4.15's builtin compat patch and isn't yet in `typescript-eslint`'s peer range.
- **DB**: SQLite by default at `data/corvid.db` (see `backend/app/core/config/settings.py` — `DatabaseSettings`, env prefix `DB_`). Logs at `data/logs/`.
- **Deploy**: `docker-compose.yaml` — `backend` (no exposed port, mounts `./data`) + `frontend` (nginx, port 4000). `make up`/`make rebuild` etc. (`make help`). `backend/docker-entrypoint.py` starts as root only to `chown` the bind-mounted `./data`, drops to non-root `appuser` (UID 1000), runs migrations (see below), then `execvp`s uvicorn. `docker-compose.prod.yaml` (installer) pins images via `CORVID_VERSION` (`update.sh [version]`). Tool state under `appuser`'s home (maigret DB, pyppeteer Chromium, subfinder config, amass engine's `~/.config/amass/asset.db`) is build-time, not bind-mounted — reset on container recreate (scan results themselves persist in the DB).

## Backend architecture

Entry point: `backend/main.py` — builds the FastAPI app via `create_fastapi_application()`, lifespan hooks create DB tables, run app defaults, start one background task running the post-startup catch-ups sequentially (`_STARTUP_CATCHUPS`: favicons, blacklist, registry dumps — each writes to single-writer SQLite), start scheduler, start the Telegram bot polling loop.

Layout under `backend/app/`:
- `core/` — cross-cutting concerns (`config/`, `settings/`, `security/ssrf_guard.py`, `reports/`, `alerts/`, `backup/`, `telegram_bot/`, `registry_dumps/`, `database.py`, `scheduler.py`, `dependencies.py`, `exceptions.py`, `healthcheck.py`). `registry_dumps/` (`common.py`/`scheduler.py`) is the shared "download → validate → all-or-nothing table replace → provenance row → staleness-driven refresh" plumbing behind every locally cached list dump (`ru_business_check`'s three, `sanctions_search`'s one) — a new dump-backed feature adds a thin `dump_jobs()`/`register_*_scheduler()` wrapper (see `ru_business_check/service/registry_dump_scheduler_service.py`). `external_sources/` is the shared third-party response-shape guard and outcome vocabulary (`docs/adr/0022-external-source-contract.md`). Deep-dive: `docs/architecture/core-cross-cutting.md` (alerts: `docs/architecture/notifications.md`; backup/restore: `docs/adr/0010-backup-restore-design.md`; `telegram_bot/`'s polling loop, the first persistent background task in this codebase: `docs/adr/0012-telegram-bot-polling.md`).
- `features/` — one directory per product feature, each typically split into `routers/`, `service/`, `schemas/`, `models/`, `crud/`, `utils/`, `config/`:
  - `newsfeed/` — RSS aggregation, IOC extraction from articles, MITRE ATT&CK mapping, trends/analytics. Per-feed `last_fetched_at`/`last_success_at`/`last_error` (set by `process_feed_chunk` each scheduler run) surface a failing feed as a UI warning. Each feed also has a nullable Admiralty `reliability` grade (A-F; `PATCH /api/settings/modules/newsfeed/{name}/reliability` accepts only A-F, so a grade is never NULL), pre-set for `DEFAULT_NEWSFEEDS`, backfilled once by `create_default_newsfeeds`; shown as a badge on article cards, filterable via `min_reliability` on `GET /api/newsfeed/articles` (unrated excluded) and passed to the article-analysis prompt.
  - `ioc_tools/` — `ioc_lookup` (single + bulk IOC lookups against AbuseIPDB, AlienVault, VirusTotal, Shodan, etc., plus a keyless local `blacklist` provider for EVM/Bitcoin addresses), `ioc_extractor`, `ioc_defanger`, `domain_finder` (typosquat/phishing discovery plus a dozen keyless/optional-key subdomain, DNS, history, and host-probe panels - full list in the deep-dive). Deep-dive: `docs/architecture/ioc-tools.md`.
  - `email_analyzer/` — `.eml` parsing, header/IOC checks, AI-assisted analysis.
  - `image_tools/` — EXIF/metadata extraction (`exifread`+Pillow, optional richer `exiftool` pass), hashing, reverse image search deep-links, an optional AI photo-geolocation hypothesis, a GPS chapter with external geo-tool deep-links (+ optional Street View embed), and an opt-in ChronoVerify provenance check. Deep-dive: `docs/architecture/image-tools.md`.
  - `llm_templates/` — user-defined AI prompt templates (categories + templates).
  - `cvss_calculator/` — CVSS 3.1/4.0 scoring.
  - `username_search/` — three sources behind one unified schema (`ScanRequest.source`: `maigret` in-process, `social_analyzer` CLI subprocess, keyless `threat_actor_usernames`; `POST /api/username-search/scan`, one scan per selected source), plus follow-up runs and pivots. Deep-dive: `docs/architecture/username-search.md`.
  - `email_search/` — which mail providers a username is registered at (`mailcat-osint`, in-process, SSE), an explicit-click Google Profile panel via GHunt (isolated venv, `docs/adr/0018-isolated-tool-cli-venvs.md`), and a manifest-gated `user_scanner` full-address source (`docs/adr/0019-user-scanner-email-source.md`). Deep-dive: `docs/architecture/email-search.md` / `docs/architecture/ghunt.md`.
  - `phone_search/` — checks a single E.164 phone number's registration on Amazon, Microsoft, and Facebook via their own sign-in/account-recovery flows; in-house checkers rather than wrapping [gophoner](https://github.com/M4elstr0m/gophoner) (its license forbids redistributing it, and it's Go, not Python). Single number per scan, no bulk, by design. Why: `docs/adr/0016-phone-search-in-house-checkers.md`.
  - `reddit_search/` — a Reddit user's full post/comment history, including removed/deleted content, from Arctic Shift and PullPush (keyless, merged and deduped). Deep-dive: `docs/architecture/reddit-search.md`.
  - `dork_runner/` — ephemeral parameterized dork templates run against a domain/username/email, DuckDuckGo by default. Deep-dive: `docs/architecture/dork-runner.md`.
  - `youtube/` — ephemeral video metadata lookup (keyless tier), plus counts/tags and comment search behind an optional YouTube Data API key (service key `youtube`). Deep-dive: `docs/architecture/youtube.md`.
  - `instagram_search/` — ephemeral public profile metadata via `instaloader`, plus a followers/followees/posts scan on the `ScanRun` lifecycle; an optional imported session cookie (never a password) is a JSON `Apikey` (`instagram_session`). Deep-dive: `docs/architecture/instagram-search.md`.
  - `git_recon/` — wraps [gitcolombo](https://github.com/Soxoj/gitcolombo) in-process to correlate names/emails/GitHub logins from commit history (`search`/`url`/`nickname` modes, `github_pat` key). `git clone` is a subprocess outside `ssrf_guard`'s reach, gated by `validate_github_repo_url`. Deep-dive: `docs/architecture/git-recon.md`.
  - `amass/` — active DNS/ASN enumeration via OWASP Amass, shelled out to; v5 needs its collection engine, started as a background subprocess on the first scan (`docs/adr/0013-amass-engine-in-container.md`). Own route `/amass/*`. Deep-dive: `docs/architecture/amass.md`.
  - `ru_business_check/` — Russian-market due-diligence by ИНН/company name (`POST /api/ru-business-check/scan`): live registry lookups plus scheduled local dumps, feeding one risk engine (`flag_engine.py`). Only ИНН-precise sources produce hard flags, and a failed or drifted source is "not checked", never empty. UI/report text is Russian-only by design. Deep-dive: `docs/architecture/ru-business-check.md` (why: `docs/adr/0014-*.md`).
  - `sanctions_search/` — ephemeral free-text name search against the *full* OFAC SDN list via its own dump of OpenSanctions' cleaned CSV (`core/registry_dumps/`), in-house exact/substring matching. Why separate from `ru_business_check`'s ИНН-exact OFAC subset: `docs/adr/0017-*.md`.
  - `steam_recon/` — Steam profile lookup plus an SSE friends-graph scan (close friends by mutual-connection weight, a geolocation hypothesis, an optional transparent CS2 cheater heuristic), Steam Web API key required (service key `steam`). Clean-room, no ML model (`docs/adr/0015-steam-recon-clean-room-and-heuristic-scoring.md`). Own route `/steam-recon/*`. Deep-dive: `docs/architecture/steam-recon.md`.
  - `activity/` — read-only `GET /api/activity`: newest runs across every `ScanFeature` (via `scan_reconciliation_registry.all_scan_features()` + each one's `target_column`) plus IOC-lookup/Reddit history, shown on the start screen; `GET /api/activity/active`: every unfinished run, `queued` vs `running` from `ScanRun.is_queued` (in-memory only), behind the AppBar's active-scans indicator.
- **Access control**: no user accounts (single-user tool) — `core/security/access_control.py` guards every `/api/*` route (plus `/openapi.json`) behind one shared bearer token (`verify_access_token`, wired as a router-level dependency in `router_registry.py`). Token comes from `API_ACCESS_TOKEN` or is auto-generated and persisted to `<data_dir>/.access_token` (0600, `persisted_secret.py`), printed once at startup; `POST /api/settings/access-token/regenerate` (`core/security/routes.py`, Settings → About) rotates it immediately, unless `API_ACCESS_TOKEN` pins it. `router_registry.get_public_routers()` lists the only unguarded routers: healthcheck, the alerts `ws_router` (checks the token via `?token=`, since a WS handshake can't carry a custom header), and newsfeed feed icons (`<img src>`, same limitation); `/docs`/`/redoc` are public data-free shells that fetch the guarded `/openapi.json` with the SPA's token (`core/config/docs_pages.py`, non-production only).
- All routers are aggregated in `backend/app/utils/router_registry.py` via `get_core_routers()`, `get_settings_routers()`, `get_feature_routers()`, then mounted in `main.py`.
- Migrations: Alembic, config at `backend/alembic.ini`, scripts in `backend/migrations/versions/`. `docker-entrypoint.py` runs `alembic upgrade head` automatically (as `appuser`, after the data-dir chown) before exec'ing the app — a failed migration aborts startup. History was squashed to one from-scratch base revision (`docs/adr/0001-squash-migration-history.md`); later schema changes are incremental revisions on top. Manual run: `docker compose run --rm backend alembic upgrade head`. `main.py`'s startup lifespan also calls `Base.metadata.create_all()` independently, which is what bootstraps local dev that never runs a migration.
- Tests: `backend/tests/`, run with pytest (`pytest.ini` sets `testpaths = tests`, `pythonpath = .`). New or substantially-changed feature logic should ship with tests in the same change — Codecov (`pytest-cov`/`vitest --coverage`, uploaded from CI on every push, badge in `README.md`) reports coverage numbers but has no configured threshold that fails CI on a drop, so nothing else in this repo catches untested code before it merges. Both sides count every source file toward the denominator, not just ones a test happens to import (backend: `backend/pyproject.toml`'s `[tool.coverage.run] source`/`[tool.coverage.report] include_namespace_packages` — most of `app/` is implicit namespace packages, which coverage.py's unexecuted-file walk skips by default; frontend: `frontend/vite.config.js`'s `coverage.all`/`coverage.include`) — expect the reported percentage to run noticeably lower than a bare `--cov=app`/default vitest setup would show.
- CI (`.github/workflows/ci.yml`): tests, a docker-build smoke test, blocking lint (ruff; mypy via `scripts/check_mypy_baseline.py`, failing only on errors not in `backend/mypy-baseline.txt` — `--update` after fixes; eslint/`tsc`), report-only CVE scans (`pip-audit`/`yarn npm audit`/Trivy — unfixable transitive findings likely). CodeQL and gitleaks are separate blocking jobs.
- `.github/workflows/release.yml` (tag push `v*.*.*`) builds multi-arch (`amd64`/`arm64`) images pushed by digest, then merged into one manifest list per image, which gets a CycloneDX SBOM and a Sigstore build-provenance attestation in GHCR (`gh attestation verify oci://ghcr.io/<owner>/corvid-backend:<tag> --owner <owner>`; why post-merge: `docs/adr/0005-sbom-attestation-on-merged-manifest.md`).
- `.github/dependabot.yml`: pip/npm (frontend + website)/docker/actions updates on the 1st and 15th, 14-day `cooldown` (supply-chain mitigation).
- `.pre-commit-config.yaml`: gitleaks, `ruff check --fix`/`ruff format` on staged `backend/` files, and local hooks that regenerate `docs/database-schema.md` (model change) and `extension/generated-ioc-patterns.js` (IOC-detection change) — a resulting diff fails the hook, so `git add` it and re-commit — plus the new-`ioc_lookup`-provider docs gate and the dangling-`docs/`-reference check. mypy stays CI-only. Setup: `pre-commit install`.
- `docker-compose.yaml`'s `backend` service loads a root `.env` (see `.env.example`) via `env_file` (`required: false`); compose's automatic `.env` loading alone only substitutes variables in the compose file, not the container environment.

## Frontend architecture

`frontend/src/features/` mirrors the backend feature split — one directory per module, same names as the backend dirs (kebab-case), plus `rule-creator` (Sigma/Yara/Snort rule builder, frontend-only) and `settings`. Each feature dir typically has its own `components/`, `hooks/`, `services/` (API calls), `constants/`, `utils/`. Entry: `src/App.jsx` → `src/index.jsx`. `src/core/` holds shared/cross-feature code.

MUI 9's `Box`/`Stack`/`Grid` only style through the `sx` prop — top-level shorthand props (`display`, `p`/`m`, `justifyContent`, ...) are silently inert (forwarded as invalid DOM attributes) rather than erroring, so a regression only shows up as a broken layout, not a build failure. `eslint.config.mjs`'s `no-restricted-syntax` rule blocks it; see `docs/adr/0009-mui-box-shorthand-props-removed.md`.

i18n: `frontend/src/core/i18n/` (`en`/`ru`, one JSON per feature namespace). When batch-translating a feature via subagents, see `frontend/I18N_PATTERN.md` — don't duplicate the code pattern/rules/deliverable format in each subagent's prompt, point at that file instead (only pass scope/namespace/output per subagent). Default to English-only for new keys/features — add `ru` only when explicitly asked; existing `ru` coverage is otherwise incomplete on purpose right now.

New top-level features also need: a `{path, Component}` entry in `src/core/config/featureRoutes.js`; a `MAIN_MENU_ITEMS_CONFIG` entry in `sidebarConfig.jsx` (one left-panel `section`, `aliases`/`tags`/`accepts` — the command palette's `commandRegistry.js` derives from it); for sub-tabs a tabs config + `TAB_ROUTES` entry (flat sets render as `FeatureTabs`, only nested Newsfeed as the `SidebarTabs` drawer); a `utils/historyPaths.js` entry (scan features); a `router_registry.py` entry; a `website/` stub page. i18n namespaces are auto-discovered from `locales/en/<camelCase>.json`. `.github/scripts/check-feature-completeness.mjs` (+ `check-docs-coverage.mjs`) fails CI with one checklist per feature; deliberate gaps go in its `EXEMPT` map. Feature pages title themselves via `core/components/ui/PageHeader`.

**Command palette** (`/` or `⌘K`/`Ctrl+K` from anywhere): framework-free grammar parser (`core/utils/commandParser.ts`) plus a JS port of the backend's IOC-type detection kept in sync via a shared test fixture. Cross-feature "send to X" actions and the palette's `value tool` pivot both prefill a target feature via a `?q=` query param — any new single-value "identity" feature needs to wire this correctly or the pivot silently drops the value; cheap one-shot lookups instead keep `?q=` as state via `core/hooks/useUrlQuery.js` (see the deep-dive for both). Deep-dive: `docs/architecture/command-palette.md`.

## Documentation site

`website/` is the public docs site at `https://z0rats.github.io/corvid/` — the deep reference for
every feature, setting, and deployment concern; `README.md` stays a short pitch that links out to
it rather than duplicating detail. Separate from this repo's internal `docs/` (ADRs, plans, audits
— those stay repo-only). Built with **Astro + Starlight** (Vite-based, matches the frontend's
tooling), own `package.json`/`yarn.lock` (Yarn 4, `nodeLinker: node-modules`, not part of any
workspace). Content lives under `website/src/content/docs/` as Markdown/MDX, sectioned
`getting-started/`, `usage/`, `architecture/`, `features/` — `astro.config.mjs`'s sidebar is
`autogenerate` per section, so a page's frontmatter `sidebar: { order: N }` (gapped by 10; omit
it and the page just sorts to the end of its section, per Starlight's own fallback) is the only
place its nav position is declared. Ground new pages in the actual source (routers/schemas), not
recollection, and never link an external URL you haven't confirmed (verify via package metadata
rather than guessing a project's GitHub org). A new top-level feature just needs a stub page under
`features/` — `.github/scripts/check-docs-coverage.mjs` (see Frontend architecture above) gates the rest.
Deploys via `.github/workflows/docs.yml` on every push to `main` touching `website/**`.

## Conventions worth knowing

- Settings/config uses `pydantic-settings` with per-domain `BaseSettings` subclasses, each with its own `env_prefix` (e.g. `DB_`, `LOG_`, `API_`, `SCHEDULER_`), all loaded from a single `.env` (gitignored, not present in repo — none committed).
- A recurring `add_recurring_job` scheduler job's `IntervalTrigger` countdown lives only in-memory and resets on every process restart (no persistent job store) — on a host that restarts more often than the interval, the job can silently never fire. Any job whose data would otherwise go stale needs a startup-time catch-up check that re-derives staleness from the DB itself (e.g. `blacklist_refresh_service.is_blacklist_stale`, checked in `main.py`'s `_populate_blacklist_if_stale_in_background`), not just an empty-table check.
- `core/config/log_redaction.py`'s `SecretRedactionFilter` is on every logging handler (`logging_config.py`) and scrubs API-key-shaped substrings (query params, `Bearer` tokens, IPQualityScore's path-embedded key) from every record, since several IOC providers (Hunter.io, Pulsedive, Shodan, Google Safe Browsing, IPQualityScore) put the key in the URL and `httpx.HTTPStatusError`'s `str()` embeds it. Pattern-based, so new providers are covered.
- In route handlers, prefer injecting settings via dependency (`SettingsDep`) rather than importing the module-level `settings` singleton, so tests can override via `app.dependency_overrides`.
- Feature module layering pattern: `routers` (HTTP) → `service` (business logic) → `crud` (DB access) → `models`/`schemas`. New features should follow this same split.
- File-upload endpoints (`image_tools`, `email_analyzer`) share their read-validate-dispatch shape via `core/utils/file_upload.py`: `validate_uploaded_file(file, *, no_file_code, read_error_code, validate_fn)` reads and validates against a feature's own `validate_file_upload(filename, size) -> (is_valid, error_code, error_message)`, returning raw bytes or raising a 400 `AppHTTPException`; `run_file_endpoint(service_fn, *args, error_code, failure_message, value_error_code=None, run_in_thread=True)` dispatches the service call (via `asyncio.to_thread` unless `run_in_thread=False`, for an already-async `service_fn`) and maps `ValueError`/other exceptions to a 422. A new upload endpoint should use these rather than duplicating the try/except.
- Third-party response shapes: a parser raises `SourceDriftError` (`core/external_sources/contract.py`'s `require_*`) when the shape changes and returns empty only for a legitimately empty answer; `classify(exc)` → `SourceOutcome` is the one skip/fail policy canaries use. `domain_finder` providers surface drift as `<CODE>_SCHEMA_DRIFT`, `ioc_lookup` providers declare `ProviderSpec.expects` or a reasoned exemption (gates: `test_domain_provider_contract.py`, `test_provider_expects_gate.py`) — a new source needs a drift case.
- Any external tool behind a UI-facing feature (maigret, social-analyzer, mailcat-osint, gitcolombo, ...) must expose its installed version, pinned so it can't drift silently: `requirements.txt` (Python packages), the Dockerfile (binaries like `exiftool`/`subfinder`/`httpx`, exact tag not `@latest`, a distinct name if it clashes with a Python package), or an isolated-venv stage when dependencies conflict (`docs/adr/0018-isolated-tool-cli-venvs.md`). Read it via `importlib.metadata` (main-venv package) or `core/utils/cli_tool_version.py`'s `get_cli_tool_version`; latest-on-PyPI via `pypi_version_check.py`'s `check_for_update` (persisted) or `fetch_latest_pypi_version`. Updating still needs a container rebuild.
- Scan-style features (SSE-streamed, cancellable, persisted run history) declare one `core/scans/feature.py` `ScanFeature` per scan table (runs, alerts, cancel, history) and mount history routes via `core/scans/routes.py`'s `add_run_routes`; frontend: `core/hooks/useResumableScan` (owns the transport, given `endpoint`). Every `ScanFeature` must be in `utils/scan_reconciliation_registry.py` (test-enforced) or its runs stay `running` after a restart, and names its `target_column` for the activity feed. Resource-heavy runs pass `heavy=True` to queue behind `SCAN_MAX_CONCURRENT_HEAVY` slots, so they must start subprocesses inside `run_work`. History lists/details use `core/components/HistoryTable`/`HistoryDetailHeader` (paging, filter/sort, live refresh of running rows, JSON/CSV export). All SSE goes through `core/scans/sse.py`'s `sse_stream` / `core/services/sseStream.ts`. Deep-dive: `docs/architecture/scan-lifecycle.md`.
- A new notification-worthy event (anywhere, not just scans/scheduler jobs) should call `core/alerts/service/alerts_service.py`'s `raise_alert()` rather than inventing its own delivery — it's the shared in-app-alert (AppBar bell, polled - `docs/adr/0020-alerts-inbox-polling.md`) + optional-Telegram-push entrypoint. Deep-dive: `docs/architecture/notifications.md`.
- New models needing row-creation/last-write timestamps should mix in `core/models/mixins.py`'s `TimestampMixin` (`created_at`/`updated_at`) rather than declaring the columns by hand — existing tables use 6 different ad-hoc names for the same concept. Domain-meaningful times (`started_at`/`completed_at`, `fetched_at`) are a different concept and keep their own names.
- AGPL-3.0 licensed (≤ v0.1.0 MIT) — mind this when adding dependencies or discussing licensing.
- Minimize new dependencies — prefer implementing small pieces of functionality ourselves over pulling in a library for it. Reach for a dependency only when the functionality is genuinely non-trivial (crypto, parsing, protocol handling) or already a de facto standard in this stack.
- Complexity budget: a file pushing ~1000 lines, or a function over ~150 lines / 8 parameters, is a signal to decompose — not a hard cap, but a prompt to split rather than keep growing it.
- Review a change in a fresh session, not the one that wrote it, against the matching sections of `docs/review-areas.md` (concurrency, untrusted input, source drift, secrets, cancellation, ...). A bug class that ships past review earns an item there.
- After fixing a bug, ask whether the same failure class could reach through a different surface; if so, prefer a structural test/gate that makes the whole class impossible over patching the one instance (e.g. `tests/core/test_ssrf_guard_coverage.py`, `tests/features/git_recon/test_url_allowlist.py`).
- A new `ioc_lookup` provider needs `website/src/content/docs/features/ioc-tools.md` updated in the same change — a pre-commit hook (`scripts/check_new_ioc_provider_docs.py`) blocks a commit that grows `service_registry.py`'s provider count without it. If it takes an API key, source `supported_ioc_types` from `service_config.py`'s matching `ServiceDefinition` rather than re-declaring it — a signature test fails if the two disagree.
- Any code that makes an HTTP request to a URL/host supplied (directly or indirectly) by the user must go through `core/security/ssrf_guard.py`'s `safe_get` — otherwise it's an SSRF vector into the docker network, localhost, or cloud metadata endpoints; `tests/core/test_ssrf_guard_coverage.py` fails on a new raw `httpx`/`requests` client that isn't on its reviewed fixed-host allowlist. Every external source (registry entry or fixed-host client) also needs a `Covered`/`Exempt` entry in `tests/canary/coverage_map.py` (gate: `tests/core/test_canary_coverage.py`).
- Security headers are set in two places, since the backend never sees the SPA's response: `core/config/security_config.py`'s `SecurityHeadersMiddleware` covers `/api/*`, `/docs`, `/redoc`, `/openapi.json` (CSP relaxed for `cdn.jsdelivr.net` + an inline init script on `/docs`/`/redoc` only, static shells with no user content); `frontend/nginx.conf`'s `location /` sets the same base headers + a strict CSP for the SPA. HSTS is production-only (`ENVIRONMENT=production`), never sent over plain HTTP.
- Lock files `backend/requirements.txt` (runtime; all the image installs) and `requirements-dev.txt` (+ pytest/ruff/mypy; CI and local venvs) are compiled from their `.in` via `uv pip compile <in> -o <txt>` — regenerate both, runtime first, never hand-edit (`-P <pkg>` bumps one package); `tests/core/test_requirements_locks_in_sync.py` catches drift. `maigret[pdf]` is the direct requirement since its extra provides the PDF stack `core/reports/` needs.

## Useful commands

`make help` lists all targets (Docker lifecycle, `test`/`test-backend`/`test-frontend`, `lint`/`lint-backend`/`lint-frontend`, `migrate`, `sync-backend`) with the exact invocations CI uses — prefer these over hand-typing `pytest`/`yarn`/`ruff`/`mypy` flags. Notes beyond what `make help` shows:

- `make lint-backend` runs `ruff check`/`ruff format --check` and the mypy baseline check (config: `backend/pyproject.toml`) — same gates as CI — and needs the synced venv below.
- `make test-backend`/`lint-backend` need a synced local venv first — run `make sync-backend` (a stale/partial venv can pass locally while missing an import error CI's full install would catch, or vice versa).
- Frontend dev server (no Docker target for this): `cd frontend && yarn start` (uses `--openssl-legacy-provider`).
- Docs site dev: `cd website && yarn dev`; build: `yarn build` (output `website/dist/`).
- App served at `http://localhost:4000` once containers are up.
