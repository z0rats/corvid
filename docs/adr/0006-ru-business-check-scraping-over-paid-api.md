# RU Business Check scrapes official ФНС sites directly, not a paid ЕГРЮЛ API

`ru_business_check`'s Stage 1 pulls its ЕГРЮЛ/ЕГРИП extract and disqualified-persons check by scraping `egrul.nalog.ru` and `service.nalog.ru/disqualified.do` directly (`features/ru_business_check/service/egrul_service.py`, `disqualified_persons_service.py`) rather than going through a paid reseller API (DaData, Kontur.Focus, Checko.ru, list-org.com) or an unofficial wrapper service (parser-api.com, api-assist.com). Both would be more reliable — a commercial reseller handles ФНС's own rate-limiting/CAPTCHA and layout drift on its end — at the cost of a recurring third-party dependency with its own pricing and availability.

The module's whole value proposition, stated in its own spec, is being built on official, publicly-open sources only — that's the explicit contrast drawn against services that quietly rely on scraped/reseller data or worse. Routing the core ЕГРЮЛ lookup through a paid intermediary would undercut that from the first release. The tradeoff accepted instead is fragility: government sites change markup without notice, and the scrapers' field extraction (particularly `egrul_service.py`'s PDF-text regex parsing, `docs/adr/` not being the place for the details — see that module's own docstring) will need real fixture-based regression tests and periodic verification against a live capture, since this repo's own sandbox has no way to browse the live sites during development.

CAPTCHA/rate-limiting from either site is treated as a hard stop — the scan fails that source cleanly with a user-facing message — never something to solve or route around. Automating past a site's own anti-bot measure isn't "scraping the same data a human would see," it's detection evasion, and it would just as directly undercut the "official sources only" positioning as paying a reseller would.

This calculus is specific to Stage 1's two sources. `arbitration` (Stage 2) has a genuine official API and doesn't raise this question at all; `fssp`/`fedresurs` (Stage 3) will face the same fragility-vs-reliability tradeoff and should default to the same answer for the same reason, re-evaluating only if scraping the ЕГРЮЛ/РДЛ sites in practice turns out to be unworkable.

## Addendum (Stage 3 re-evaluation)

Live testing against both real sites (not just documentation) settled the re-evaluation this ADR called for, with an asymmetric outcome:

- **fedresurs.ru** (bankruptcy): scraping worked. Its own search backend (`fedresurs.ru/backend/companies`/`/persons`) is keyless and CAPTCHA-free — confirmed by direct requests, including a live-observed anti-bot block (HTTP 451 from Qrator on an overly broad query) that behaves exactly like `arbitration_service.py`'s existing DDoS-Guard handling. Built as `service/fedresurs_service.py`, same pattern as Stage 1-2.
- **fssp.gov.ru**: scraping is not viable, full stop — not a fragility tradeoff to accept, a hard blocker. Its official free API (`api-ip.fssp.gov.ru`) is dead (`HTTP 410 Gone`, consistent with ФССП's own April-2022 letter about the API's discontinuation). Its public web search's real AJAX endpoint (`is-go.fssp.gov.ru/ajax_search`) was hit directly with a real ИНН query and returned an image-CAPTCHA challenge on the very first, unthrottled request — unlike kad.arbitr.ru/fedresurs.ru, where blocks only trigger under abuse. Automating past that would mean solving a CAPTCHA on literally every scan, which this project's never-bypass-CAPTCHA policy rules out categorically. `fssp` stays a manual deep-link in the UI, not a scraped source.
- **Movable-property pledges** (`reestr-zalogov.ru`) turned out to be a separate registry entirely — run by the Federal Notary Chamber, not Fedresurs, despite both being colloquially lumped under "Федресурс" in early planning. Its pledgor/INN search endpoint is *not* CAPTCHA-gated (confirmed from its own webpack bundle — only a different, single-notification lookup calls a captcha widget), so it's a plausible future addition, but its exact JSON request-body shape couldn't be pinned down from static analysis alone within a reasonable session budget. Deferred, not abandoned — needs a live browser network capture to finish.
